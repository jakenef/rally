# Idea history

How we got to Rally, so nobody re-litigates it. Brainstormed 2026-11-06 with Claude.

The prompt: improve the state of Utah. Track: Best Commerce Project (helps a business sell to or serve customers). Wanted: ambitious, technical, uses AI, buildable in a few hours, ideally touching the BYU vs. Utah Holy War (2026-11-07) without taking sides.

## Considered

| Idea | One line | Verdict |
|---|---|---|
| Swing | Shops write promos in plain English; an agent fires them from the live game feed | Strong; tied to one weekend |
| Dead Hours | Empty venue slots sold as group-date bundles across venues | Strong, not tied to the game |
| Rally | Pickleball facilities sell balanced games instead of court time | **Picked** |
| Moment Merch | Big plays trigger short shirt drops for both fan bases | Good Holy War backup |
| Powder Desk | Dynamic pricing for ski rental shops from snow and canyon data | Too much fake data |
| KSL Closer | AI sales agent for KSL Classifieds sellers | Scraping terms risk |
| Holy War Exchange | Ticket resale prices as a stock chart with Kronos forecasts | Experimental model |
| Fill the Gap | Voice agent phones the waitlist to fill a cancelled slot | Folded into Rally as backfill |
| Agent-Ready Main Street | WebMCP so agents can book local venues | Interesting, preview-only tech |
| Dirty Soda Copilot, Gateway Concierge | Voice ordering; tourist concierge | Rejected as generic |

## Why Rally

- Real Utah problem (packed courts, chaotic open play).
- Clear buyer (facilities) and clear money (premium sessions, recovered cancellations).
- Technical depth: computer vision, a matching optimizer, ratings, an agent for backfill.
- Distinct from DUPR once the rating is an input instead of the product (see `positioning.md`).
